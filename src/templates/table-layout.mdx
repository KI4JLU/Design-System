# TableLayout

Table/admin pages: a `PageHeader` with actions, a `Card` with an optional
toolbar (search/filter), the table as `children` in a horizontally scrollable
zone, and an optional footer (pagination). Sorting, filtering and pagination
logic stays in the app.

<Canvas of={TableLayoutStories.Admin} />

## Slots & props

| Slot / prop | Type | Required | Content |
|---|---|---|---|
| `title` | `ReactNode` | ✅ | Page title — a real heading, level set by `headingLevel`. |
| `headingLevel` | `1`–`6` | — | Level of the title in the document outline. Default `1` (so `<h1>`) — unchanged for every existing call site. `2` or lower for a page whose `<h1>` is already carried by the frame (admin shell, CMS). The typography does **not** depend on the level. |
| `description` | `ReactNode` | — | Muted line below the title. |
| `actions` | `ReactNode` | — | Header actions on the right (e.g. "Neu anlegen"). |
| `toolbar` | `ReactNode` | — | Search/filter row in the card, above the table. |
| `children` | `ReactNode` | ✅ | The table (`Table`, or a `<table>` with token classes). |
| `footer` | `ReactNode` | — | Row below the table: result count on the left, pagination on the right. |

## Responsive behavior

- A full `Container` with token page margins; the header stacks on mobile.
- Wide tables scroll horizontally **inside the card** (`overflow-x-auto`) —
  the page itself never breaks out horizontally.
- Toolbar and footer are `flex-wrap`: filters wrap on narrow screens.

## Do's & don'ts

- ✅ Fill status columns with `Badge tone=…`; row actions as a
  `DropdownMenu`.
- ✅ Table colors only via tokens (`border-outline-variant`,
  `text-on-surface-variant`).
- ❌ No second `<h1>` on the page: the rule and the `headingLevel` it calls for are in `docs/COMPONENT_GUIDELINES.md` → "Page headings: who owns them".
- ❌ Don't "make table columns fit" by shrinking the font — wide tables scroll
  horizontally.
- ❌ No filter/sort logic in the template; the toolbar is a slot, not a
  feature component.
