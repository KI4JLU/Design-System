# SectionedGridLayout

The overview page: a **stack of collapsible sections, each with a card
grid**. Optionally a title row (`PageHeader`) above, then per group a header
row (title, icon, count, action) and a body — either a `Grid` of cells, an
empty-state line or a free-form node.

This template is **page content**. It goes into `AppShellLayout` as
`children`, and the shell owns the brand, the page label and the user menu.
Why content templates and the shell are two kinds: `docs/DESIGN_SYSTEM.md`
§4 → "Page templates".

## Slots & props

| Slot / prop | Type | Required | Content |
|---|---|---|---|
| `label` | `string` | ✅ | Accessible name of the `region` landmark around the whole content. Required: per HTML-AAM a `<section>` **without** a name is `generic`, so not a landmark at all. |
| `sections` | `SectionedGridSection[]` | ✅ | The sections in display order (see the tables below). |
| `headingLevel` | `1`–`6` | — | **One** number for both heading roles: the page title sits at this level, every section heading one level below. Default `1` ⇒ `h1` + `h2`, exactly as before. Applies **without** `title` too — the prop says *where* the page title is, not only whether this template draws it. Clamped above level 6. |
| `title` | `ReactNode` | — | Page title. Set ⇒ a `PageHeader` at `headingLevel` above the sections, as in `DashboardLayout`. Leave it out when the title only sits in `AppShellLayout`'s `pageLabel` row. **Or the other way round** (since 0.29.0): keep `title` here and leave `pageLabel` off the shell — that is the more accessible choice, because only this heading is in the outline; the label is a `<p>`. |
| `description` | `ReactNode` | — | Muted line below the title (needs `title`). |
| `actions` | `ReactNode` | — | Right-aligned actions next to the title (needs `title`). |
| `cols` | `1 \| 2 \| 3 \| 4` | — | Default `3`. Column count of **all** section grids on desktop; the collapse comes from `Grid`. One control for the whole page — sections with different column counts read like different pages. |
| `...rest` | `HTMLAttributes<HTMLElement>` | — | Lands on the root `<section>`. |

### `SectionedGridSection` — header row

| Field | Type | Required | Content |
|---|---|---|---|
| `id` | `string` | ✅ | Stable id from the app. React key **and** suffix of the disclosure's element ids; the template prepends a `useId()` prefix so two instances on one page don't collide. |
| `title` | `ReactNode` | ✅ | Section heading. Rendered **one level below** `headingLevel` — so `<h2>` by default. |
| `icon` | `ReactNode` | — | Leading icon in the header row (lucide, `aria-hidden`). |
| `count` | `number` | — | Count as a neutral `Badge` next to the title — **inside** the trigger, so part of its accessible name ("Favoriten 3"). |
| `headerAction` | `ReactNode` | — | Control at the end of the header row, deliberately **outside** the trigger: clicking it doesn't toggle the section (nested buttons would also be invalid HTML). |
| `isOpen` | `boolean` | ✅ | Open/closed — **consumer state**. |
| `onOpenChange` | `(isOpen: boolean) => void` | ✅ | Trigger pressed; carries the **requested** state, never the old one. |

### `SectionedGridSection` — body: exactly one of three forms

The form is a TypeScript union (with `never` locks): the **wrong
combination** is therefore a type error. In the code it stays a precedence
chain (`emptyState` → `body` → `Grid`) — so a JS consumer without type
checking who passes two forms silently gets that order. The reason for the
union: the template must **not infer** whether a section is empty.
`React.Children.count` over a mapped array, a fragment or a `false` can't be
told apart predictably — and the app already branches itself anyway (the
reference implementation writes `list.length === 0 ? <empty/> : <grid/>` on
every section). So the app picks the form, the template renders it, and there
is no third state that can be wrong.

| Form | Fields | Result |
|---|---|---|
| Card grid | `items: ReactNode`, optional `createCell: ReactNode` | `items` as cells of a `Grid cols={cols}`; `createCell` is the **first** cell of the same grid (not a separate row above it). |
| Empty state | `emptyState: ReactNode` | Instead of a grid, a muted line (`text-body-base text-on-surface-variant`) — pass a string; typography and color belong to the template. |
| Free form | `body: ReactNode` | Rendered raw, **without** `Grid` — for a section whose content isn't a card grid but a whole panel (catalog/discover, table, filtered list). |

## Collapsing: controlled, and **not** an accordion

The design system has no `Accordion` primitive, and this template doesn't
smuggle one in. Every section is a **disclosure** (ARIA/APG) made of a button
+ panel:

- `aria-expanded` on the button, `aria-controls` pointing at the panel
  element.
- The button sits **inside** the `<h2>` (the APG's accordion markup), so the
  section stays reachable via heading navigation while the whole row is still
  the click target.
- The panel `<div>` is **always** in the DOM (with `hidden` when closed). An
  `aria-controls` pointing at an id that exists only in the open state would
  be a dangling reference: it passes an "attribute present" check, but
  nothing is announced.
- The panel's **children** are unmounted on collapsing. That is intentional
  and load-bearing: in the reference implementation (`KbAccordion`) the
  catalog panel's fetch hangs on mount, so expanding is the re-read. It is
  deliberately the opposite of `SidePanel`, which keeps its children mounted
  so a half-typed input survives a collapse — a card grid has nothing to lose,
  a form does.
- The panel gets **no** `role="region"`: a disclosure doesn't need one, and
  the APG explicitly warns against landmark sprawl from ~6 panels up. This
  template provides exactly **one** landmark, its own `<section aria-label>`.

The state lives with the app — as with `SidePanel` and `AppShellLayout`. There
is **no** `defaultOpen`: a template that remembers things would be a second
source of truth next to the app state. If you want to persist the sections
(the reference implementation does so via `localStorage`), do it in the app
and pass the result in.

## Responsive behavior

All CSS, **no** `matchMedia`:

- **Card grid**: `Grid cols={cols}` brings the collapse (`3` ⇒ 1 column, 2
  from `md`, 3 from `xl`). The app writes no breakpoint ladder.
- **Title row**: `PageHeader` stacks title and actions below `md`.
- **Section header row**: `flex-wrap`; the `headerAction` moves to the next
  line when needed.

Unlike `AppShell`, this template never renders a structurally different tree
per viewport — so it needs no viewport knowledge, and there is no second
breakpoint here.

## Accessibility

- One landmark: `region`, named via `label`.
- **No second `<main>`.** The shell's `<main>` already holds this template,
  so its own region is a `<section aria-label>` (the rule:
  `docs/DESIGN_SYSTEM.md` §4 → "Page templates").
- Heading order: one number, two levels. `headingLevel` (default `1`) is the
  page title's level, and the sections sit one level below — so by default
  exactly one `h1` (from `PageHeader`) and one `h2` per section. Without
  `title` the page starts at `h2`, because the title then lives elsewhere
  (e.g. in `AppShellLayout`'s `pageLabel`). If the page sits in a frame that
  already carries the `h1`, `headingLevel={2}` shifts **both** levels together
  (`h2` + `h3`) — before, these were two hard-wired levels that couldn't move
  together. Clamped above level 6: HTML has no `h7`.
- Focus: the trigger carries the system's `focus-ring` recipe
  (`focus-visible:ring-2 ring-focus-ring` + offset).
- The chevron is `aria-hidden` and rotates via `transition-transform` with
  `motion-reduce:transition-none`; `aria-expanded` announces the state, not
  the icon.

## Do's & don'ts

- ✅ Hang the template in as `children` of `AppShellLayout` — templates
  compose into each other.
- ✅ Keep the open/closed state in the app (URL parameter, context,
  `localStorage`) and pass it in.
- ✅ Decide grouping, sorting and the "own vs. shared" split of items in the
  app; the sections come in ready-made.
- ✅ Pass the create cell as `createCell` — it is a cell of the grid, not a
  row of its own.
- ❌ No `defaultOpen`, no "the template remembers": exactly one state, and it
  lives in the app.
- ❌ No accordion rebuilt in the app and no disclosure of your own — if
  something is missing, this template is extended here.
- ❌ No second grid in the section body: cells belong in `items`, so all
  sections share the same column logic. `body` is for content that is *not* a
  card grid.
- ❌ No page scaffolding in here (logo header, legal notice, FAB): those are
  shell or app concerns.

## Open points

- The **name** (`SectionedGridLayout` instead of `IndexLayout`/`HomeLayout`)
  and the decision that collapsing **unmounts** the body still need the
  design system owner's approval — both are marked as `TODO` in the code.
- The cells are deliberately not a list (`<ul>`/`<li>`): `Card` renders a
  `<div>`, and `Grid` would have to be turned into a list via `asChild`. If a
  consumer needs list semantics, that is an extension here, not a rebuild in
  the app.
- There is **no** dedicated typography token for the sections' `h2`: it uses
  `font-headline-md text-headline-md-mobile` (20px, without the `md:` jump),
  so the section heading stays below the `h1` (24px). A `title-*` token would
  be a token proposal per DESIGN_SYSTEM.md §6.
