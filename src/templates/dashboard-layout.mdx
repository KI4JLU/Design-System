# DashboardLayout

Overview pages: an optional toolbar row (search/filter) first, then the
`PageHeader` (title, description, actions), an optional KPI row in a
responsive grid, and free content below. Usually sits as `children` in
`AppShellLayout`. Fetching and aggregating data stays in the app — the
template owns only the skeleton.

## Slots & props

| Slot / prop | Type | Required | Content |
|---|---|---|---|
| `toolbar` | `ReactNode` | — | Search/filter row above the title, e.g. `ListToolbar` with `FilterMenu`s. |
| `title` | `ReactNode` | ✅ | Page title — a real heading, level set by `headingLevel`. |
| `headingLevel` | `1`–`6` | — | Level of the title in the document outline. Default `1` (so `<h1>`) — unchanged for every existing call site. `2` or lower for a page whose `<h1>` is already carried by the frame (admin shell, CMS). The typography does **not** depend on the level. |
| `description` | `ReactNode` | — | Muted explanatory line below the title. |
| `actions` | `ReactNode` | — | Header actions on the right, in the same row as the title — e.g. a time-range switch, export, or a muted count of entries (`text-on-surface-variant`). |
| `stats` | `ReactNode` | — | KPI tiles — laid out in a 4-column grid (`Grid cols={4}`). |
| `children` | `ReactNode` | ✅ | Free content; use `<Grid>` for card grids. |

## Responsive behavior

- The content sits in a `Container` (page margins `gutter` → `margin-page`,
  max width `container-max`).
- The stats row wraps 4 → 2 → 1 columns (`Grid cols={4}`); the `PageHeader`
  stacks title and actions on mobile.

## Do's & don'ts

- ✅ Build content grids with `<Grid>`, spacing only via token gaps.
- ✅ Use existing components (Card, Badge, SegmentedControl) as content.
- ❌ No second `<h1>` on the page: the rule and the `headingLevel` it calls for are in `docs/COMPONENT_GUIDELINES.md` → "Page headings: who owns them".
- ❌ No breakpoint ladders of your own at the call site — the grid
  breakpoints live in `Grid`.
- ❌ Don't pull data/loading logic into the template; spinners and empty
  states are content, not layout.
