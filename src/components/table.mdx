# Table

The part set for real HTML tables: `Table`, `TableHeader`, `TableBody`,
`TableFooter`, `TableRow`, `TableHead`, `TableCell`, `TableCaption`. Replaces
the hand-styled `<table style={{…}}>` blocks in the admin views and the
Markdown table overrides in the chat surfaces.

Deliberately **without Radix** — Radix Primitives has no table primitive, and
the shadcn template itself imports only React and `cn` (checked against the
file `shadcn add table` generates). Native table markup already carries the
accessibility contract; a JS layer on top could only break it.

## Props

| Prop | Part | Type | Meaning |
|---|---|---|---|
| `containerClassName` | `Table` | `string` | Classes for the scroll container **around** the table (layout, e.g. `max-h-72` for vertical scrolling). The only access to that container. |
| `className` | `Table` | `string` | Classes for the `<table>` itself (e.g. `table-fixed`). |
| `scope` | `TableHead` | `'col' \| 'row' \| …` | Default `'col'`. Decides whether the cell is announced as a `columnheader` or a `rowheader` — not how it looks. |
| `colSpan` / `rowSpan` | `TableCell`, `TableHead` | `number` | Native attributes; for empty-state and total rows. |
| `data-state="selected"` | `TableRow` | `string` | Marks a selected row (`bg-secondary-container`). The shadcn convention for data-table recipes. |
| `wrap` | `TableHead`, `TableCell` | `'anywhere' \| 'words'` | Default `'anywhere'` (`wrap-anywhere`: also breaks mid-word, for hashes/URLs). `'words'` (`wrap-break-word`) breaks only between words — for headers and short labels, where a split like "Sehe-n" is worse than a slightly wider column. |
| `group` | `TableHead` | `boolean` | Column-group heading over `colSpan` columns: centered, semibold, label underlined in the primary color; `scope` becomes `'colgroup'` (an explicit `scope` wins). |
| `divider` | `TableHead`, `TableCell` | `boolean` | Vertical line on the cell's leading edge — the boundary between two column groups, set in the header **and** the body. |
| `density` | `Table` | `'default' \| 'compact'` | Default `'default'`. `'compact'` makes the whole table denser: `text-xs`, 32px header rows, `p-1.5` in the cells, a smaller group heading and caption. Header and body cells read the value from context; the call site needs no font-size or padding classes. |
| `muted` | `TableHead`, `TableCell` | `boolean` | A column that is shown but cannot be changed here (e.g. a role that always has every permission): a tinted band (`surface-container`), quieter text (`on-surface-variant`). Set it on **every** cell of the column, header included. |
| `section` | `TableHead` | `boolean \| 'band'` | Row-group heading: the label row above a group of rows. `scope` becomes `'rowgroup'` (an explicit `scope` wins), a small semibold uppercase label; the row gets no hover tint and no line. `true`: a plain label with space above. `'band'`: the whole row becomes a tinted band (`surface-container`). |
| `count` | `TableHead` | `ReactNode` | Only with `section`: a count after the label, quieter and not in uppercase. Part of the accessible name, with a comma that is only read aloud: "Quellen in der Sidebar, 4". |
| `mutedEdge` | `TableHead`, `TableCell` | `'top' \| 'bottom'` | Rounds the end of the band: `'top'` on the header cell, `'bottom'` on the last body cell. Only works together with `muted`. |
| `mutedJoin` | `TableHead`, `TableCell` | `'start' \| 'middle' \| 'end'` | Joins neighboring muted columns into **one** band: `'start'` on every cell of the first, `'end'` of the last, `'middle'` of the columns in between. No gap and no rounding at the seams, rounded only on the outside. Only works together with `muted`. |

All parts pass remaining props and `ref` through to their native element
(`<table>`, `<thead>`, `<tr>`, `<th>`, `<td>`, `<caption>`).

## Overflow: the table scrolls in its own container

`Table` brings its own scroll container (`relative w-full overflow-x-auto`) —
the call site needs **no** extra `overflow-x-auto`. That is both the shadcn
shape and this repo's convention: `TableLayout` and the Markdown overrides in
the apps already do exactly this.

## Column groups

A second header row above the column headers groups columns together:
`TableHead group colSpan={n}` per group, `divider` on the first column of
every further group (group head, column head and every body cell). A
row-heading column on the left spans both header rows with `rowSpan={2}`.
There is exactly **one** line under the header: `TableHeader` removes the
bottom line from every header row except the last, and the groups'
underlines separate the two header rows. The underline sits on the label, not
on the cell, so it is indented by the cell padding — two neighboring groups
don't run into each other.

<Canvas of={TableStories.GroupedColumns} />

## Dense tables

`density="compact"` on `Table` for matrices that have to fit into a narrow
column: smaller text, lower header rows, tighter cells. The density applies to
every part of the table — font-size or padding classes at the call site are
not needed (and are unwanted on DS building blocks per lint rule anyway). A
class at the call site still wins, as everywhere.

## Muted columns

A column whose values are fixed (owner and admin always have every
permission) becomes a tinted band with `muted` on each of its cells; the
header cell gets `mutedEdge="top"`, the last body cell `mutedEdge="bottom"` —
that is where the corners are rounded. Between two muted cells the band runs
across the row line, so the column reads as one piece. Two neighboring muted
columns stay two bands separated by a narrow gap — unless `mutedJoin` joins
them: then the gap and the rounding at the seam disappear, and only the outer
corners of the shared band are rounded (owner + admin in the matrix below).
Sides and corners are logical (start/end), so the band mirrors in RTL.

The band is a `::before` layer behind the cell content, not the cell's own
background: according to CSS Backgrounds 3, `border-radius` has no effect on
table cells under `border-collapse: collapse`, and Tailwind's Preflight sets
that on every table.

## Row groups

A label row divides the rows below it into groups (THEMA, QUELLEN IN DER
SIDEBAR, ANTWORTEN): `TableHead section` as the first row of each group, each
group in its own `TableBody` — that is the row group `scope="rowgroup"` refers
to. The heading is announced as a `rowheader`. Its row doesn't change color
on hover and draws no line: `TableRow` detects it itself (`:has()` on
`data-slot="table-section-head"`); the call site doesn't mark the row.

`section="band"` turns the whole row into a tinted band (`surface-container`),
and `count` puts a quieter count after the label. The band is **one** inset
shadow on the row, not a row background: Chromium paints a row background
cell by cell and leaves 1px hairlines between the cells when column widths are
fractional.

The heading spans all columns with `colSpan` — but a heading cell that spans a
muted column covers its band. So that the column band runs through the
section row, the heading sits only in the columns before the first muted one,
and the remaining cells of the row are empty `TableCell`s
(`muted`/`mutedJoin` in the muted columns). In a band row the table paints
that crossing one step darker (`surface-container-high`): the column band
stays visible and the section band lies across it. `RotatedMatrixPlain` shows
the plain form without a band.

<Canvas of={TableStories.RotatedMatrixPlain} />

The hover exclusion is tested only as a class: Testing Library's `hover`
fires events but never puts the row into the CSS `:hover` state. The story
instead measures that the same `:has()` variant applies in the browser (no
line under the row).

## Decisions

- **The container has no `role` and no `tabindex`.** A `<div>` without a role
  is invisible to the accessibility tree, so the structure
  `table → rowgroup → row → columnheader/cell` stays unchanged. A
  `role="region"` would create an extra landmark; the APG warns against
  landmark sprawl (the same reasoning as for the `SectionedGridLayout` panel),
  and most screen readers discard an **unnamed** region anyway. A
  `tabindex={0}` would be the WCAG 2.1.1 answer for scrollable areas — but
  here it would put a nameless tab stop in front of *every* table, while the
  table contents (links, buttons) are already reachable by keyboard.
- **Cells wrap by default** — unlike the current shadcn template, which puts
  `whitespace-nowrap` on every cell. The reason is the existing code: none of
  the eight tables found in JustRAG and CampusAgents sets `nowrap` across the
  board; the JustRAG dashboard sets it per column, and both Markdown tables
  wrap on purpose. `whitespace-nowrap` therefore belongs on the individual
  cell (date, number), not in the template.
- **`wrap-anywhere` on header and data cells.** Long unbroken strings (hashes,
  API keys, URLs) break inside the cell instead of making the table wider than
  its container. Matches the `overflow-wrap: anywhere` the CampusAgents
  Markdown table sets by hand today.
- **Every divider carries a color (`border-outline-variant`).** Tailwind's
  Preflight sets `border: 0 solid` without a color, so `border-b` alone renders
  in `currentColor` — this repo (unlike shadcn) has no global `border-border`
  reset. A bare `border-b` taken over as is would have drawn the lines in the
  text color.
- **The header row is quieter than the content** (`text-on-surface-variant`,
  `font-medium`) — all five admin tables in JustRAG already do this today
  (`var(--text-secondary)`).
- **Without the template's `data-slot` attributes and checkbox helpers.** The
  exceptions are `data-slot="table-group-head"` on the group head and
  `table-section-head` / `table-section-count` on the row-group heading, so a
  call site can find them without a class selector (and `TableRow` can detect
  the heading row with `:has()`); and
  `[&>[role=checkbox]]:translate-y-[2px]` is an arbitrary value for a recipe
  (row selection) no call site uses yet.

## Deliberately not included

- **Sticky header.** No call site has one today; the one candidate
  (the vertically scrolling "Low-Score-Queries" in the JustRAG dashboard)
  doesn't have one either. It isn't free, either: Tailwind's Preflight sets
  `border-collapse: collapse` on `<table>`, and with collapsed borders the
  header row's bottom edge doesn't move along with the `position: sticky`
  element — it would also need `border-separate border-spacing-0` or a shadow.
  That is a decision of its own (owner) and a card of its own, not a by-product
  of this one.
- **Sorting, filtering, pagination, row selection.** That is logic and stays
  with the app; `TableLayout` has the `toolbar` and `footer` slots for it.
- **Zebra stripes.** The row hover (`bg-surface-container-high`) guides the
  eye along the row; a second change of surface would compete with it.

## Scope: `Table` vs. `TableLayout`

- **`Table` is the table**, `TableLayout` is the **page**: PageHeader, card,
  toolbar slot, footer slot. They don't exclude each other — the normal case
  is `Table` as the `children` of `TableLayout`.
- `TableLayout` puts its own `overflow-x-auto` around its `children`, because
  non-tables can sit there too. Together with `Table`'s container that makes
  two nested scroll containers; the inner one takes effect. Not a bug, but the
  reason why a call site should **never** add a third `overflow-x-auto`.
- A table without a page frame (a Markdown answer in the chat, a table in a
  dialog) uses `Table` **without** `TableLayout`.

## Markdown tables

`react-markdown` passes its AST node to component overrides as a `node` prop;
it must not be spread onto a DOM element. The call site filters it out:

```tsx
<ReactMarkdown
  components={{
    table: ({ node, ...p }) => <Table {...p} />,
    thead: ({ node, ...p }) => <TableHeader {...p} />,
    tbody: ({ node, ...p }) => <TableBody {...p} />,
    tr: ({ node, ...p }) => <TableRow {...p} />,
    th: ({ node, ...p }) => <TableHead {...p} />,
    td: ({ node, ...p }) => <TableCell {...p} />,
  }}
/>
```

## Do's & don'ts

- ✅ `TableCaption` for every table that doesn't sit directly under its own
  heading — it is the table's accessible name.
- ✅ The empty state as **one row with `colSpan`** across all columns; the
  header row stays (story "Empty").
- ✅ `whitespace-nowrap` specifically on cells that should never wrap (date,
  amount, actions).
- ✅ Height for vertical scrolling via `containerClassName`.
- ❌ No extra `overflow-x-auto` at the call site — the container belongs to
  the component.
- ❌ No tables for layout. If you only want columns, use `Grid` or `Stack`; a
  `<table>` is announced as a data table.
- ❌ No empty `<tbody>` as the empty state — a table without rows tells screen
  reader users nothing.
- ❌ No colors or font sizes at the call site (rule 4 of the
  COMPONENT_GUIDELINES); alignment (`text-right`) and wrapping behavior are
  layout and stay allowed.

## Accessibility

- Native semantics are fully preserved. Per HTML-AAM they map to:
  `<table>` → `table`, `<thead>`/`<tbody>`/`<tfoot>` → `rowgroup`, `<tr>` →
  `row`, `<th scope="col">` → `columnheader`, `<td>` → `cell`.
- `TableHead` sets `scope="col"` by default — that is what makes the cell a
  column header. For a row heading set `scope="row"`.
- `TableCaption` provides the accessible name: a table with a caption can be
  found with `getByRole("table", { name })`. The `<caption>` must be the
  `<table>`'s first child in the DOM (HTML content model); `caption-bottom`
  displays it at the bottom.
- The scroll container adds nothing to the accessibility tree (no `role`, no
  `tabindex`) — see "Decisions".
- Tested in `table.test.tsx` against the HTML-AAM role mapping and the
  accessible-name computation, not against the implementation.
