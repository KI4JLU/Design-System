# BottomTabBar

The mobile area switch: a `<nav>` landmark fixed to the bottom edge with N
tabs of icon + label; the active one carries `aria-current="page"`.

<Canvas of={BottomTabBarStories.Playground} />

## Props

| Prop | Type | Required | Meaning |
|---|---|---|---|
| `items` | `{ id, icon, label }[]` | ✅ | Tabs in display order. `icon` is a `ReactNode` (e.g. a lucide icon) and is set to 20px by the component. |
| `activeId` | `string` | ✅ | Id of the current tab. An id without a matching entry marks **no** tab. |
| `onChange` | `(id: string) => void` | ✅ | Click/key press on a tab. |
| `label` | `string` | ✅ | Accessible name of the `<nav>` landmark. |

## Not a SegmentedControl

Checked before this component was built: `SegmentedControl` is a
`role="group"` of `aria-pressed` toggles for a **value within** a page (time
range day/week/month), inline in the flow, without icons. This bar is **app
chrome**: a navigation landmark that switches which view the viewport
shows — and that is exactly what `aria-current="page"` means. A different
role, a different landmark, a different placement. A shared component would
have two ARIA contracts.

## Decisions

- **Generic.** No fixed ids, orders or labels — the consumer provides
  `items`. Whether and how the active tab is derived from other state stays
  with the consumer; the bar renders what it is told.
- **`aria-current="page"` instead of `aria-selected`.** No `tablist`: there
  are no tab panels in the ARIA sense, only switched views. Tabs are
  `<button>`s and are therefore operated with Tab, Enter and Space without any
  keyboard logic of their own.
- **Height 60px**, the same chrome unit as `SIDE_PANEL_RAIL_WIDTH`, plus
  `env(safe-area-inset-bottom)` for the iOS home bar. Touch target per tab at
  least 44px.
- **`fixed` is the default.** A consumer that needs the bar in the flow
  overrides the position via `className` (layout, not skin — `cn()` resolves
  the conflict).
- **The icon is decorative** (`aria-hidden`): a tab's accessible name is
  exactly its `label`.

## Do's & don'ts

- ✅ Pass icons without a size — the bar sets them uniformly.
- ✅ Translate `label`; the landmark needs a name in every language.
- ❌ Don't pass app logic in (which view belongs to which id).
- ❌ Don't use it as a replacement for `SegmentedControl` in forms or toolbars.
