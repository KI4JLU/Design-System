# Tooltip

A short hint for a control that already has its accessible name. Replaces
`title=` attributes (invisible to keyboard and touch users, not stylable) and
hand-built hover hints. Radix provides the APG tooltip pattern:
`role="tooltip"`, an `aria-describedby` link to the trigger, opening on hover
**and** focus, and Escape closes it.

## Props

| Prop | Part | Type | Meaning |
|---|---|---|---|
| `delayDuration` | `Tooltip` | `number` | Delay in ms before opening on hover (default `0` — shadcn convention; focus always opens immediately). |
| `open` / `defaultOpen` / `onOpenChange` | `Tooltip` | — | Controlled/uncontrolled as with all Radix primitives. |
| `asChild` | `TooltipTrigger` | `boolean` | Renders your own element (button, icon button) as the trigger — the normal case. |
| `side` | `TooltipContent` | `'top' \| 'right' \| 'bottom' \| 'left'` | Placement, default `top`; moves aside automatically when there is no room. |
| `sideOffset` | `TooltipContent` | `number` | Distance to the trigger, default `6`. |
| `align` | `TooltipContent` | `'start' \| 'center' \| 'end'` | Alignment along the side. |

## Provider

No app setup needed: every `Tooltip` brings its own `TooltipProvider`
(shadcn shape). `TooltipProvider` is still exported — but an app-wide provider
does **not** change the component's defaults, because the built-in inner
provider wins. Deviations (for example a delay) are set per instance with
`delayDuration` on the `Tooltip`.

## Decisions

- **`bg-primary` + `text-on-primary`, not panel surfaces.** That is the
  shadcn template, remapped through the token table in
  COMPONENT_GUIDELINES.md. The contrast with the page distinguishes the
  fleeting hint from the anchored panel (`Popover`:
  `surface-container-lowest`).
- **No animation, no arrow.** Like all floating surfaces in the system
  (Popover, Select, DropdownMenu) — which also trivially satisfies
  `prefers-reduced-motion`.
- **Disabled triggers need a focusable wrapper.** A `disabled` button fires no
  pointer events; the trigger then wraps a `<span tabIndex={0}>` around the
  button (see story "DisabledTrigger"), otherwise the reason it is disabled is
  unreachable.

## Catch-all for `title=`: `TitleTooltips`

`<TitleTooltips />`, mounted once at the app root, shows this tooltip instead
of the browser tooltip for **every** element with a native `title`
attribute — also for titles added later, third-party markup and portals.
While the pointer or keyboard focus is on the element, the `title` is emptied
(the text goes to `data-title`) and written back afterwards; if React changes
it in the meantime, the new value applies; if React empties or removes it,
that stays. For screen readers nothing changes: if the title was the name, it
becomes the `aria-label` for that time, otherwise the description
(`aria-describedby`), unless it only repeats the name. The pointer may move
onto the tooltip (150 ms grace period); in fullscreen it lands in the
fullscreen element.

- Plain text only (line breaks are kept). Rich content still needs an
  explicit `Tooltip`.
- Makes nothing focusable: a `title` on a `span` stays unreachable for
  keyboard and touch. Disabled buttons fire no pointer events (see above).
- Elements inside an explicit `TooltipTrigger` are skipped;
  `data-native-title` on an ancestor turns the catch-all off for the subtree.
- Tone: primary like `Tooltip`; under `[data-tooltip-tone="inverse"]`
  (`Message` sets it) the inverse surface, as for `MessageAction`.

## Do's & don'ts

- ✅ Icon buttons: `aria-label` stays the name, the tooltip only describes.
- ✅ Keep it short — a sentence fragment. Anything longer belongs in a
  `Popover` or on the page.
- ❌ No essential content or actions only in the tooltip — it isn't reachable
  on touch devices.
- ❌ No tooltip as a substitute for a missing label (`aria-label` / `Label`
  first).
- ❌ No interactive elements in the tooltip (links, buttons) — that is what
  `Popover` is for; a tooltip never receives focus.
- ❌ No additional `title=` attribute — otherwise the screen reader reads the
  hint twice.

## Accessibility

- The content carries `role="tooltip"`; the trigger is linked to it via
  `aria-describedby` (only while it is open) — the hint is read after the
  control's name.
- Opens on hover **and** keyboard focus, closes on Escape, blur and pointer
  leave.
- The tooltip itself is never focusable and is not in the tab order.
- Tested in `tooltip.test.tsx` against the APG pattern (describedby
  resolution, opening on focus, Escape, not focusable).
