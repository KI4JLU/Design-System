# Toast

A short status message in a fixed corner of the screen: `ToastProvider`,
`ToastViewport`, `Toast` + `ToastTitle` / `ToastDescription` /
`ToastAction` / `ToastClose`. Replaces hand-built message stacks — in JustRAG
`components/ToastContainer.tsx` + `Toast.css`, whose timer is a bare
`setTimeout` that nobody can pause.

Built on Radix (`@radix-ui/react-toast`). That brings along: the live-region
announcement (see "Accessibility"), one timer per toast that **pauses** on
hover, focus and window switch and resumes with the remaining time, the
**F8** shortcut into the viewport, swipe to dismiss, and Escape.

## Three parts, or nothing happens

```tsx
// once around the app
<ToastProvider>
  <App />
  {toasts.map((t) => (
    <Toast key={t.id} variant={t.variant} onOpenChange={(o) => !o && remove(t.id)}>
      <ToastTitle>{t.message}</ToastTitle>
      <ToastClose />
    </Toast>
  ))}
  <ToastViewport />
</ToastProvider>
```

A `Toast` **without a mounted `ToastViewport` renders nothing at all** and
announces nothing either — in the installed Radix source, `ToastImpl` returns
`null` as long as no viewport is registered. That is the most likely wiring
mistake; `toast.test.tsx` pins it down.

The viewport is rendered **once**. A second one gives every toast a second
home and the stack falls apart.

## Props

| Prop | Part | Type | Meaning |
|---|---|---|---|
| `label` | `ToastProvider` | `string` | Prefixed to the announcement of **every** toast ("Benachrichtigung: Datei gespeichert"). Default `"Benachrichtigung"` — singular, it is not the viewport's name. |
| `swipeDirection` | `ToastProvider` | `'right' \| 'left' \| 'up' \| 'down'` | Swipe direction to dismiss, default `right`. |
| `label` | `ToastViewport` | `string` | Accessible name of the region; `{hotkey}` is replaced by the key. Default `"Benachrichtigungen ({hotkey})"`. |
| `hotkey` | `ToastViewport` | `string[]` | Key that moves focus into the viewport. Default `["F8"]`. |
| `variant` | `Toast` | `'neutral' \| 'success' \| 'error' \| 'warning' \| 'info'` | Status. Decides surface and text color (like `Alert`), icon, default duration **and** the urgency of the announcement. Default `neutral`. |
| `icon` | `Toast` | `ReactNode \| false` | Replaces or suppresses the status icon. |
| `duration` | `Toast` | `number` | Display time in ms. Without it, the variant's time (see below). `Infinity` = no auto-dismiss. **Not `0`** — see "Pitfalls". |
| `type` | `Toast` | `'foreground' \| 'background'` | Overrides the urgency of the announcement (`assertive` / `polite`). |
| `open` / `onOpenChange` | `Toast` | `boolean` / `(open) => void` | The usual Radix contract. `onOpenChange(false)` is the hook where the app takes the toast out of its list. |
| `altText` | `ToastAction` | `string` | **Required.** What a screen reader hears **instead of** the label — describes the alternative way to the action. Empty text: Radix doesn't render the action at all. |
| `aria-label` | `ToastClose` | `string` | Name of the close button, default `"Schließen"`. |

All parts pass remaining props and `ref` through to their Radix primitive.

## Who owns the queue?

**The app, not the design system.** Which toasts exist, how many stand at the
same time and in which order is application state — just as with every other
component here. JustRAG keeps a reducer with `MAX_TOASTS = 5` for it; that
limit stays there. The design system provides the presentation and — through
Radix — the timer per toast.

So the way from JustRAG's `ToastContext` to here is short: the list stays,
the `setTimeout` in `ToastItem` **goes away** (Radix takes it over, including
the pause), and `removeToast(id)` hangs on `onOpenChange`.

## Durations

| Variant | Default | Reason |
|---|---|---|
| `success`, `info` | 4000 ms | Only confirms what just happened. |
| `warning`, `neutral` | 5000 ms | Radix default. |
| `error` | 6000 ms | Carries something still to be done — stays readable longer. |

The values are those of the existing implementation in JustRAG
(`DEFAULT_DURATIONS`), exported as `TOAST_DURATIONS`.

## Decisions

- **Radix Toast, not `sonner`.** shadcn now recommends `sonner`, but it brings
  a complete toast machine with its own state, its own markup and its own CSS.
  This package consists of thin Radix wrappers (`dependencies` are only
  `@radix-ui/react-*` plus cva/clsx/tailwind-merge/lucide), styles through
  tokens and keeps application state out on principle. `sonner` would break
  all three — and the queue it ships already exists in JustRAG.
- **Errors are announced `assertive`, everything else `polite`.** An error
  toast says that what the user just triggered did **not** happen; a polite
  queue may hold that announcement back for any length of time — by then the
  toast is gone. Everything else only confirms and doesn't justify an
  interruption. Can be overridden per toast with `type`.
- **No hand-written `role="alert"`** — and none needed: `role="alert"` is
  defined as `aria-live="assertive"` + `aria-atomic="true"`, and exactly that
  configuration comes out of the error path (see "Accessibility").
- **No enter/exit animation**, as with all floating surfaces in this system
  (Tooltip, Popover, Select, DropdownMenu). That makes
  `prefers-reduced-motion` not "respected" but moot: there is no motion to
  reduce. The existing implementation in JustRAG animates with Framer Motion —
  and its `getMotionProps(reduced)` is spread there **before**
  `initial`/`animate`/`exit`, the later props win, so the reduction has no
  effect. One more reason not to bring the animation along.
- **The status icon belongs to the variant**, not to the call site. It is what
  keeps the status from being conveyed by color alone (WCAG 1.4.1); it is
  `aria-hidden` because the message itself already says what happened.
  `icon={false}` turns it off; `variant="neutral"` has none by default.
- **The newest toast is on top** (`flex-col-reverse` on the bottom-anchored
  viewport). That is the direction JustRAG has too, and it matches Radix's tab
  order: its `getSortedTabbableCandidates` reverses the collection, so Tab
  also visits the newest first. Visual and focus order match.
- **`z-100`, above `Dialog` and `BottomTabBar` (`z-50`).** A toast triggered
  from inside a modal must not disappear behind it. The two layers don't
  interfere: the viewport is a `DismissableLayer.Branch`, so a click on a
  toast doesn't close the dialog.
- **The action sits below the text, not next to it.** The toast is at most
  `sm` wide; a button next to the text would squeeze text or button — rule 5 of
  the COMPONENT_GUIDELINES.
- **Column spacing via margins instead of `gap-x`.** A CSS grid gap also
  applies between empty tracks: with `gap-x` every toast without an icon would
  be indented by 12 px. The spacing therefore sits on the icon (`mr-3`) and on
  the close button (`ml-3`).

## Pitfalls

- **`duration={0}` doesn't turn auto-dismiss off.** Radix resolves the
  duration with `durationProp || context.duration`; `0` is falsy and falls
  back to the provider value. The off switch is `Infinity`.
- **`ToastProvider duration` has no effect on this component.** `Toast`
  always resolves to a number (the prop, otherwise the variant's time), so the
  provider value never gets a turn. Set durations per toast or change
  `TOAST_DURATIONS`.
- **Escape closes toasts even when focus is somewhere else entirely.** That is
  Radix behavior (`DismissableLayer`), not an oversight of this wrapper.
- **Above a `BottomTabBar`** (60 px) the viewport covers the bar on narrow
  screens. Layout class at the call site: `className="bottom-15 sm:bottom-0"`.

## Deliberately not included

- **No `useToast`/`toast()` singleton.** That would be global application
  state in a library that otherwise has none — and it exists twice in JustRAG
  already.
- **No limit on the number** and no merging of identical messages. Both are
  decisions about the queue, so they are the app's business.
- **No progress bar for the remaining time.** It would have to mirror the
  paused state, which would make it an animation this system has nowhere.

## Do's & don'ts

- ✅ Exactly one `ToastViewport`, as high up in the app as possible.
- ✅ One-liners as `ToastTitle`; `ToastDescription` only for a real detail.
- ✅ `variant="error"` for failures — the urgency of the announcement depends
  on it.
- ✅ Toast with an action → `duration={Infinity}` and a `ToastClose` next to
  it.
- ✅ Use `onOpenChange(false)` to take the toast out of your own list —
  otherwise it stays behind as an invisible entry.
- ❌ No essential information only in a toast. It disappears and can't be
  found anywhere afterwards; what has to stay valid belongs on the page (an
  error box on the form, a status column in the table).
- ❌ No questions, no forms, no series of links — a toast carries at most
  **one** action. Everything else is a `Dialog`.
- ❌ No toast for something the user sees anyway (the row has gone, the field
  is green).
- ❌ No stacks of errors with the same cause — one message, not twenty.
- ❌ No colors, font sizes or paddings at the call site (rule 4 of the
  COMPONENT_GUIDELINES); width, position and grid placement are layout and
  stay allowed.

## Accessibility

- **It is not the visible toast that is announced.** Radix renders a
  separate, visually hidden element with `role="status"` for that, whose
  `aria-live` depends on `type`: `foreground` → `assertive`, `background` →
  `polite`. The visible toast is a plain `<li>` in the viewport's `<ol>` and
  **not a live region itself** — so the message is announced exactly once
  (counted in `toast.test.tsx`).
- **`role="status"` + `aria-live="assertive"` is the error configuration.**
  The explicit `aria-live` value overrides the role's implicit `polite`, and
  the role's implicit `aria-atomic="true"` stays — together exactly what
  `role="alert"` means by definition.
- **No focus theft.** The toast appears without moving focus; whoever is
  typing keeps typing. Tested against `document.activeElement`.
- **It still stays reachable:** the toast itself is focusable
  (`tabIndex={0}`, with a visible focus ring), **F8** jumps into the viewport,
  and Radix orders the tab sequence so that the newest toast comes first. In
  the test the close button is reached by actual Tab presses, not by looking
  at `tabIndex`.
- **WCAG 2.2.1 "Timing Adjustable":** the time limit can be extended. The
  timer pauses while the pointer is on the toast **or** focus is in the
  viewport (F8 is enough), and resumes with the remaining time — it doesn't
  restart. In addition: `ToastClose` as an explicit way out and
  `duration={Infinity}` for anything that needs a response. A separate
  "pause" switch is therefore left out.
- **WCAG 2.3.3 / `prefers-reduced-motion`:** there is no enter or exit
  animation (see "Decisions"), so nothing to reduce.
- **WCAG 1.4.1:** the status lives not only in the accent color but also in
  the icon and the text.
- Tested in `toast.test.tsx`: live-region configuration per variant and when
  overridden, exactly one announcement, announcement text including `label`
  and `altText`, no focus theft, keyboard reachability of the close button,
  default and overridden durations, `Infinity`, pause on hover **and** on
  focus, and the silent non-rendering without a viewport.
