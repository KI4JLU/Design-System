# Tabs

A tab bar plus panels: `Tabs`, `TabsList`, `TabsTrigger`, `TabsContent`.
Replaces the hand-built tab bars in the apps — rows of `<button>`s that carry
`role="tab"` but name no `tabpanel`, or, the other way round, swap panels
without identifying themselves as tabs.

Built on Radix (`@radix-ui/react-tabs`). That brings the APG "Tabs" pattern
ready-made: `role="tablist"`, `role="tab"` + `aria-selected` +
`aria-controls` per tab, `role="tabpanel"` + `aria-labelledby` per panel, a
single tab stop for the whole bar, and arrow-key / Home / End navigation
inside it.

## Props

| Prop | Part | Type | Meaning |
|---|---|---|---|
| `value` / `onValueChange` | `Tabs` | `string` / `(v: string) => void` | Controlled active tab. |
| `defaultValue` | `Tabs` | `string` | Uncontrolled initial value. Without either, **no** tab is active at first and no panel is rendered. |
| `orientation` | `Tabs` | `'horizontal' \| 'vertical'` | Default `horizontal`. Turns the bar, sets `aria-orientation` and swaps the navigation keys (←/→ ↔ ↑/↓). |
| `activationMode` | `Tabs` | `'automatic' \| 'manual'` | Default `automatic`: focus selects. `manual`: arrow keys only move focus, Enter/Space select. |
| `dir` | `Tabs` | `'ltr' \| 'rtl'` | Reading direction for the arrow keys. **The visuals are not mirrored** — see "Deliberately not included". |
| `aria-label` | `TabsList` | `string` | Name of the bar. Required as soon as there is more than one bar on the page. |
| `loop` | `TabsList` | `boolean` | Default `true` — the arrow keys wrap from the last tab to the first. |
| `value` | `TabsTrigger`, `TabsContent` | `string` | Connects tab and panel. Ends up in the generated ids (`…-trigger-<value>`), so use a **slug without spaces**, not the label. |
| `disabled` | `TabsTrigger` | `boolean` | Natively disabled button; Radix takes it out of arrow-key navigation entirely. |

All parts pass remaining props and `ref` through to their Radix primitive.

## Scope: Tabs, SegmentedControl or BottomTabBar?

The deciding question is not the look, but: **does the bar name a content
area?**

- **`Tabs`** — there is one panel per tab, and the panel's accessible name
  *is* its tab (`aria-labelledby`). The tab "Evals" names the area "Evals".
- **`SegmentedControl`** — the bar sets a **value**, and what changes is data
  in an area the bar doesn't name: a filtered catalog, the time range of a
  chart (day/week/month). The ARIA for that is `role="group"` made of
  `aria-pressed` toggles — no `tablist`, because there is no `tabpanel`.
- **`BottomTabBar`** — app chrome: a `navigation` landmark that switches which
  view the viewport shows, with `aria-current="page"`. No `tablist`, because
  there are no panels in the ARIA sense, only switched views (the same
  reasoning is in the BottomTabBar docs).

A `role="tab"` **without** a matching `tabpanel` is wrong in any case — it is
the most common existing bug in the apps. If you decide on tabs, you need one
`TabsContent` per tab; if you have none, you actually wanted
`SegmentedControl`.

## Decisions

- **Active = underline + `text-primary`, not a filled pill.** The contrast
  with `SegmentedControl` (`bg-primary text-on-primary`) is intended: the two
  patterns should be distinguishable **visually** too, not only in ARIA. The
  underline is also the shape the existing bars in JustRAG already have.
- **The active tab is only recolored, never enlarged** — the same rule as for
  `BottomTabBar`, otherwise the bar jumps on switching.
- **Tabs are not squeezed** (`shrink-0`, `whitespace-nowrap`) — rule 5 of the
  COMPONENT_GUIDELINES. If the row doesn't fit, it overflows; the scroll
  container is a layout decision of the call site
  (`className="overflow-x-auto overflow-y-hidden"`, story "ManyTabs"), unlike
  `Table`, where every call site needs it.
- **The divider sits on the `TabsList`**, the underline on the tab (`-mb-px`),
  so it sits exactly on the line. Every line carries `border-outline-variant`:
  a bare `border-b` would render in `currentColor`, because this repo has no
  global `border-border` reset.
- **The panel keeps its visible focus ring.** Radix sets `tabIndex={0}` on
  `TabsContent` (the APG requires that when the panel content isn't focusable
  itself). The shadcn template puts `outline-none` on it without a
  replacement — on a focusable element that would violate WCAG 2.4.7, so here
  it is `ring-focus-ring` instead of nothing.
- **No `orientation` prop of our own and no cva variants.** Radix mirrors the
  orientation as `data-orientation` onto **all four** parts (root, list,
  trigger, content — for the trigger via the roving focus group, checked
  against the built markup), so a `data-[orientation=vertical]:` switch in the
  classes is enough.

## Behavior to know at the call site

- **Inactive panels are not hidden but unmounted.** Radix renders only the
  active `TabsContent`; state inside it (a half-filled form, a scroll
  position) does **not** survive the switch. If you need it, lift it into the
  call site. `forceMount` is **not** a way out: it makes all panels visible at
  once, not "mounted but hidden". That is the opposite trade-off to
  `SidePanel` (stays mounted) and the same as for the `SectionedGridLayout`
  panel.
- **Without `value`/`defaultValue` no tab is active** and no panel appears at
  all. That is rarely what you want.
- The `aria-controls` of an **inactive** tab points at the id of its
  unmounted panel, so it goes nowhere. That is Radix behavior; axe-core 4.12
  doesn't flag it (measured with the Storybook a11y addon: zero violations,
  zero incomplete on a bar with an active, an inactive and a disabled tab).

## Activation mode

The default is `automatic`: moving focus with an arrow key **selects** the tab
right away. That is the APG recommendation as long as showing a panel is
cheap. If a panel costs a network call, arrowing through would load every
area — then use `activationMode="manual"`.

## Deliberately not included

- **No built-in scroll container** and no "next" arrows at the ends of the
  bar. No call site today has more than four tabs; from about eight, the
  vertical bar or a `Select` is a better answer than a scrolling row where half
  the tabs are invisible.
- **No mirrored visuals for RTL.** With `dir="rtl"` Radix flips the arrow
  keys, but the classes here are physical (`border-r`, `-mr-px`), because this
  repo has used physical utilities throughout so far. For an RTL interface that
  would be a separate, system-wide decision.
- **No lazy loading, no preloading of neighboring panels.** That is logic and
  stays with the call site.

## Do's & don'ts

- ✅ One `TabsContent` per tab — otherwise it isn't a tab.
- ✅ `aria-label` on the `TabsList` as soon as there is more than one bar on
  the page.
- ✅ Slugs as `value` (`"globale-kbs"`), not the label — the value ends up in
  the generated ids.
- ✅ Keep panel state in the call site, not in the panel.
- ✅ Icons in the tab with `aria-hidden`; the tab's name is its text.
- ❌ No `role="tab"` on a filter or toggle row without panels — that is
  `SegmentedControl`.
- ❌ No tabs for page navigation (changing the route) — that is `NavItem` /
  `BottomTabBar` with `aria-current="page"`.
- ❌ No tooltip on a disabled tab — it isn't focusable at all. Write the reason
  for the lock visibly next to it.
- ❌ No colors, font sizes or paddings at the call site (rule 4 of the
  COMPONENT_GUIDELINES); width, overflow and grid placement are layout and
  stay allowed.

## Accessibility

- `TabsList` is `role="tablist"` with `aria-orientation`; every tab is a
  `role="tab"` with `aria-selected` and an `aria-controls` pointing at its
  panel.
- `TabsContent` is `role="tabpanel"` and carries `aria-labelledby` pointing at
  **its** tab — so the panel's accessible name is the tab label.
- **One tab stop for the whole bar.** The implementation is not the APG's pure
  roving-tabindex recipe: as long as focus has never been in the bar,
  `tabindex="0"` sits on the `tablist` container and **all** tabs are at `-1`;
  on entry the container forwards focus to the active tab, and from then on
  the `0` moves with focus. From the outside it does exactly what the APG
  requires: one Tab lands on the active tab, the next Tab leaves the bar.
  (Checked against the built markup, not assumed — `tabs.test.tsx`.)
- Arrow keys move focus within the bar and wrap; Home/End jump to the
  first/last tab. Horizontal uses ←/→, vertical ↑/↓ — the other axis is
  deliberately inert.
- Disabled tabs are natively `disabled` and therefore completely out of
  keyboard navigation (the APG also mentions the `aria-disabled` variant, which
  stays focusable; Radix implements the native one).
- The panel itself is focusable (`tabIndex={0}`) and has a visible focus ring.
- Tested in `tabs.test.tsx` against the APG pattern: role and name resolution
  (`aria-labelledby` must point at **the selected** tab, `aria-controls` back
  at **this** panel), keyboard navigation in both orientations, both
  activation modes, disabled tabs.
