# Alert

A message that stays in the page until the situation changes: a list that
failed to load, a form that did not save, a note about the service. It is the
one component for inline messages — `Notice` is a deprecated wrapper over it.

```tsx
import { Alert, AlertTitle, AlertDescription, AlertAction } from "@ki4jlu/design-system";

<Alert tone="error" live="assertive">
  <AlertTitle>Speichern fehlgeschlagen</AlertTitle>
  <AlertDescription>Die Änderungen wurden nicht übernommen.</AlertDescription>
</Alert>
```

## When to use it — and when not

| Situation | Use |
|---|---|
| A state the user has to know about while they stay on the page (load failed, read-only, maintenance) | `Alert` |
| A short static hint in a form or a settings section | `Alert` without a title (`AlertDescription` only), `tone="neutral"` |
| A confirmation that fades after a few seconds („Gespeichert") | `toast()` (`Toaster`) |
| A message for the whole app (outage) | `Alert layout="banner"` in `AppShellLayout`'s `notice` |
| A question the user must answer before going on | `AlertDialog` |
| A single field's error | the field's own `aria-invalid` and message (`Form`) |

## Tones

Every status tone brings its icon, so the status is never told by colour
alone. `neutral` has none — there is no status to signal.

<Canvas of={AlertStories.Tones} />

`icon` replaces the tone's icon; `icon={null}` drops it.

## Parts

- **`AlertTitle`** — the short headline. A `div`; give it a heading level with
  `asChild` only where the alert is a section of the outline.
- **`AlertDescription`** — the message, or the detail under a title. A
  one-line alert is just this.
- **`AlertAction`** — follow-up buttons on their own row under the text
  („Erneut versuchen"), so neither text nor button is squeezed.

## Dismissing

`onDismiss` adds a close button. The alert does not hide itself: the call site
unmounts it — and moves the focus somewhere sensible, because the focused
close button goes with it.

## In context

An alert brings its own tinted surface; in a card it needs no card of its own.

## Layouts

`layout="box"` (default) is the block in the page. `banner`, `pill` and `toast`
are for `AppShellLayout`'s `notice` and `status` slots — see
`Templates/AppShellLayout → WithSystemNotice` and `WithSystemStatus`.

## Creation time

`AlertTitle time={date}` shows when the message was raised at the end of the
title row — `14:32` today, `25.11., 14:32` before, formatted for `<html lang>`
— as every toast does. Give it to the shell's floating cards (the update card,
a system notice), which sit in the toast pile. The time lives in the title
row: a message without an `AlertTitle` shows none.

Screen readers hear the full date and time (with the year), which stays the
same when the visible text gains its date at midnight — so a live alert is not
announced again. The text is filled in after hydration and follows changes of
`<html lang>`.

## Accessibility

- **`live` decides what a screen reader hears.** `off` (default): no role —
  a message that is there when the page loads needs no announcement.
  `assertive` (`role="alert"`): a message that appears because of what the
  user just did and says it failed. `polite` (`role="status"`): a non-urgent
  change; mount the region before its text changes, or it may not be read.
- The icon is `aria-hidden`: the text has to say everything on its own.
- `dismissLabel` names the close button (default „Schließen").
