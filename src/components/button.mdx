# Button

The system's button — a `<button>` with the variants from `buttonVariants`,
and via `asChild` (Radix Slot) also a link. All colors come from semantic
tokens; both themes switch by themselves.

## Variants

<Canvas of={ButtonStories.Variants} />

| Variant | For |
|---|---|
| `default` | Primary action (save, create) — one per area |
| `secondary` | Secondary action on a filled background |
| `outline` | Neutral secondary action (cancel, filter); with `aria-pressed` a toggle, with `data-state="open"` an open trigger |
| `ghost` | Quiet neutral action (icon buttons, menu triggers, close); `aria-pressed` and `data-state="open"` as with `outline` |
| `primary-outline` | Semantic "activate" toggle |
| `destructive` | The confirmation step of a deletion ("Endgültig löschen") |
| `destructive-outline` | Secondary danger next to other actions ("Deaktivieren", "Zugriff widerrufen") |
| `ghost-destructive` | Delete/remove in dialog footers, toolbars and rows |
| `link` | An action that sits like a link in running text |

## Toggle and open trigger

`outline` and `ghost` style themselves as soon as the call site sets
`aria-pressed` (filter toggles) or a Radix trigger carries
`data-state="open"` (dropdown open). The ARIA attribute is the API — no extra
prop.

## Delete is always red

**Every action that deletes or removes something uses a destructive
variant** — `ghost-destructive`, `destructive-outline` or `destructive`. Never
`ghost` or `outline` with a trash can: a neutral button next to Cancel and
Save doesn't look dangerous, not even on hover. All three destructive
variants are red at rest already (text, border or surface);
`ghost-destructive` additionally puts the error container underneath on
hover, and `destructive-outline` fills red.

<Canvas of={ButtonStories.DeleteActions} />

| Where | Variant |
|---|---|
| Dialog footer, toolbar, selection bar, table or list row (also as an icon button) | `ghost-destructive` |
| Secondary danger that stands on equal footing next to other actions | `destructive-outline` |
| The confirmation step ("Wirklich löschen?") | `destructive` |

The same applies in menus through `DropdownMenuItem variant="destructive"` or
`destructive: true` in the `ActionMenu`.

```tsx
// Row or toolbar
<Button variant="ghost-destructive" size="icon" aria-label="Quelle entfernen">
  <Trash2 aria-hidden className="size-4" />
</Button>

// Confirmation step
<DialogFooter>
  <DialogClose asChild><Button variant="outline">Abbrechen</Button></DialogClose>
  <Button variant="destructive" onClick={remove}>Endgültig löschen</Button>
</DialogFooter>
```

The remove `×` on `PromptInputAttachment` and `TokenInputChip` is red at rest
too. On hover the `×` on an attachment puts the error container underneath
(`ghost-destructive`); the `×` on a chip fills red (`error` with `on-error`),
because the error chip itself already has the error container as its
surface.

### Pattern: delete in a dialog footer

An editor whose object can be deleted (e.g. "Thema löschen" in the topic
settings): on the left of the footer a `ghost-destructive` "Löschen" next to
the status, on the right Cancel (`outline`) and Save (`default`). "Löschen"
opens a confirmation dialog whose own button is `destructive`.

<Canvas of={SettingsDialogStories.DeleteInFooter} />

```tsx
<SettingsDialog
  size="xl"
  fitTo={contentArea}
  footer={(
    <>
      <div className="flex items-center gap-3">
        <Button variant="ghost-destructive" onClick={() => setConfirming(true)}>
          <Trash2 aria-hidden="true" className="size-4" />
          Löschen
        </Button>
        <span className="text-sm text-on-surface-variant">{status}</span>
      </div>
      <div className="flex gap-2">
        <Button variant="outline" onClick={close}>Abbrechen</Button>
        <Button onClick={save}>Speichern</Button>
      </div>
    </>
  )}
  {...rest}
/>
```

The footer arranges its two children left and right; "Löschen" and the status
therefore share one left element.
