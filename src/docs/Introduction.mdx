# JLU Design System

Shared design tokens, theming and React UI components for JLU projects —
**one** look and feel, consumed as a dependency instead of copied into each
project.

- **Tokens**: two layers (primitives `--p-*` → semantic tokens such as
  `--color-primary`, `--color-surface-container-*`), light + dark.
- **Components**: based on shadcn/ui (Radix + Tailwind 4), styled only through
  semantic tokens — theming works automatically.
- **Enforcement**: an ESLint plugin (`no-hardcoded-colors`,
  `no-raw-ui-elements`) ships with the package.

## Installation

The package lives in the GitHub Packages registry (private). Add an `.npmrc`
to the project once:

```ini
@ki4jlu:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${NODE_AUTH_TOKEN}
```

Provide a token with the `read:packages` scope (locally, for example, with
`gh auth refresh -s read:packages` and `export NODE_AUTH_TOKEN=$(gh auth token)`),
then:

```bash
npm install @ki4jlu/design-system
```

## Setup (Tailwind 4 app)

In the project's main CSS file:

```css
@import "tailwindcss";
@import "@ki4jlu/design-system/tokens.css";
@source "../node_modules/@ki4jlu/design-system";
```

The `@source` entry makes Tailwind compile the library's classes too (the path
is relative to the CSS file). The app loads the fonts **Inter, Manrope**
itself (as before, for example from `index.html`).

Mount the ThemeProvider at the app root and copy the no-flash script into
`index.html` (see the "Theming" page):

```tsx
import { ThemeProvider, Button } from "@ki4jlu/design-system";

<ThemeProvider>
  <Button>Los geht’s</Button>
</ThemeProvider>
```

## ESLint enforcement (recommended)

```js
// eslint.config.js
import designSystem from "@ki4jlu/design-system/eslint-plugin";

{
  files: ["src/**/*.{ts,tsx}"],
  plugins: { "design-system": designSystem },
  rules: {
    "design-system/no-hardcoded-colors": "error",
    "design-system/no-raw-ui-elements": "warn",
  },
}
```

## Governance

Changes to tokens, component APIs and variants are reviewed by the design
system owner (CODEOWNERS). Process and rules: see `docs/DESIGN_SYSTEM.md` in
the repository.
