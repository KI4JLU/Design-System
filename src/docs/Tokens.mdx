# Design tokens

Two layers, defined in `tokens.css`:

1. **Primitives** (`--p-blue-600`, `--p-gray-100`, …) — raw values without
   meaning, **never use them directly**.
2. **Semantic tokens** (`--color-primary`, `--color-surface`, …) — describe
   intent, reference primitives and generate the Tailwind utilities
   (`bg-primary`, `text-on-surface`, `shadow-card`, …). **Use only these.**

Dark mode overrides only the semantic layer (`[data-theme="dark"]`) —
components need no `dark:` variants.

## Colors → token cheat sheet

| Need | Token utility |
|--------|---------------|
| Page / app background | `bg-surface` (text: `text-on-surface`) |
| Card / raised surface | `bg-surface-container-lowest` + `border-outline-variant` (use `<Card>`) |
| Muted text | `text-on-surface-variant` |
| Primary action | `bg-primary text-on-primary` (use `<Button>`) |
| Secondary action | `bg-secondary-container text-on-secondary-container` |
| Borders / dividers | `border-outline-variant` (stronger: `border-outline`) |
| Focus ring | `ring-focus-ring` (already built into the components) |
| Success / online | `bg-success` / `text-success`; badge: `bg-success-container text-on-success-container` |
| Info / pending | `text-info` / `bg-info-container text-on-info-container` |
| Warning | `text-warning` / `bg-warning-container text-on-warning-container` |
| "Ended" notice (caution) | `text-caution` / `bg-caution-container text-on-caution-container` |
| Error / destructive | `text-error`; button: `<Button variant="destructive">` |
| Brand wordmark (use `<Logo>`) | `text-brand-wordmark` + `bg-brand text-on-brand` (badge is theme-invariant) |
| Scrim under modals | `bg-scrim/50` (built into `<Dialog>`) |
| Elevation | see the ladder below |

If a token is missing: **don't invent a hex value**; propose a new token
through the process in `docs/DESIGN_SYSTEM.md` §6.

## Primary flips in dark mode

`--color-primary` is a **dark** blue in the light theme and a **light** one in
the dark theme — with `--color-on-primary` as its counterpart in each (M3).
That means:

- `bg-primary` **always** goes with `text-on-primary` — never with
  `text-white`. One token cannot serve as both surface and text.
- `text-primary` / `border-primary` work in **both** themes on every surface
  (10.8:1 on `surface` in the dark, 6.6:1 at worst on
  `surface-container-highest`).
- If you need the reverse — a *dark* surface with a light primary accent (for
  example on `inverse-surface`) — use `text-inverse-primary`.

`--color-brand` is not affected: the brand color is identity and stays the
same in both themes.

## Elevation — four levels

| Level | Utility | For |
|-------|---------|-------|
| 1 | `shadow-card` | resting card |
| 2 | `hover:shadow-card-hover` | raised card |
| 3 | `shadow-overlay` | popover, dropdown, select |
| 4 | `shadow-modal` | dialog, drawer |

In dark mode the opacity rises automatically (0.05 → 0.4 on level 1) —
otherwise a shadow would vanish on a dark background. The values live in the
`--elevation-*` ramp in `tokens.css`; **in components use only the four
utilities**.

## Transparent color fills (tints)

For "primary at 8 % opacity", **don't mirror a hex value** — it goes stale
silently as soon as the blue changes. Derive it from the token instead:

```css
/* CSS */
background: color-mix(in srgb, var(--color-primary) 8%, transparent);
```

```tsx
/* Tailwind — the same, shorter */
<div className="bg-primary/10" />
```

Both follow the token and switch with the theme. There is deliberately **no**
`--color-primary-rgb` token: it would have to be kept in sync with the
primitive by hand, and would be exactly the source of errors it is meant to
solve.

## Other scales

- **Typography**: `text-display-lg`, `text-headline-md`, `text-label-sm`,
  `text-stat-lg`, `text-body-base` (+ the matching `font-*` families).
- **Spacing**: `gutter`, `stack-sm/md/lg`, `margin-page`.
- **Page widths**: `container-max` (1440px), `container-content` (1000px),
  `container-reading` (42rem/672px) — the three widths that `Container size`
  names `page` / `content` / `reading`. They are referenced as
  `max-w-(--max-width-container-*)`; why not as `max-w-container-*` is
  explained in `container.mdx`.
- **Radius**: `rounded`, `rounded-lg`, `rounded-xl`, `rounded-full`.
- **Interaction states**: `primary-hover`, `primary-active`, `focus-ring`,
  `disabled`, `on-disabled`. In dark mode `hover`/`active` get lighter than
  `primary` instead of darker.
